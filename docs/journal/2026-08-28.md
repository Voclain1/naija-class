## Confirmed baseline

An isolated disposable Postgres (`127.0.0.1:55432`), Redis
(`127.0.0.1:56379`), API (`localhost:4100`) and web (`localhost:3101`) harness
was initialized with the CI SQL/migrations/seed and verified healthy. A real
390px Playwright workflow seeded a teacher with one form-teacher arm and 40
historical-term students with realistic long Nigerian names.

- Dirty marks were silently lost on date and class changes; no confirmation was
  shown and no save request was made.
- The Term summary link and browser Back also discarded dirty local state; reload
  reset the local register without a prompt.
- Status buttons measured about 38×34px, displayed only P/A/L/E, and the page
  width reached 425px at a 390px viewport. Notes were only about 33px wide in
  the table layout.
- A forced 503 retained dirty marks, re-enabled Save and allowed a successful
  retry. However, status buttons remained editable while a held save was in
  flight, so a subsequent reload could overwrite a newer local change.

## Change

- `AttendanceRegisterPage` receives the editor dirty count and protects date,
  class, in-app link, browser Back, reload and close exits only while there are
  unsaved marks.
- `RegisterEditor` now has explicit saving/saved/failed feedback, preserves
  dirty marks after failure, offers Retry save, and disables all editor changes
  during a write. A ref closes the fast second-submit race.
- Mobile rows become compact cards below `sm`, with 44px keyboard-focusable
  status targets, non-colour P/A/L/E legend and full-width note input.
- The isolated E2E config accepts explicit API/web URLs and skips launching
  normal-port servers only when `E2E_ISOLATED=1`; CI defaults are unchanged.
