WhatsApp sharing and school-name display, but exposed the per-link synthetic
email in Paystack's parent-facing greeting. Code inspection confirmed names
were already sent as `SchoolKit` / `Payment`; the proposed “just add names”

## Invoice read defects — arm filter and issuer display

The production follow-up exposed two independent invoice-read defects. First,
the invoice list UI sent `classArmId` and the shared schema accepted it, but
`InvoiceGenerationService.findAll()` discarded the field. The selector was a
silent no-op. Second, the invoice detail rendered the internal `issuedBy` user
UUID directly.

Branch `fix/invoice-read-display-and-arm-filter` fixes both without widening
permissions. Arm filtering resolves exact tenant-scoped `(studentId, termId)`
enrollment pairs, preserving historical correctness when a student moves arms
between terms. Issuer names are batch-resolved inside the existing
tenant-scoped invoice read and exposed as `issuedByName`; the UUID remains only
for internal attribution and is never a display fallback.

The real-Postgres invoice suite passes 37/37. Its new paired evidence proves an

to `Bisi Owner`. API/web typechecks and linters pass. A real local Dev Bursar

correct empty state for an arm with no invoices.
