# 2026-10-19 — Codex app visual refresh

Owner requested a UI-only refresh of the main web and mobile apps, inspired
by four supplied Yuyu screenshots. Work is on `design/app-visual-refresh`;
production has not been changed.

## Changed

- White light-mode content surfaces on the existing Paper canvas, green-grey
  borders and muted surfaces, softer corners and subtle elevation.
- DM Sans throughout staff web/portal; Hanken Grotesk throughout mobile.
  Legacy display aliases keep the many inline headings consistent. Removed
  unused display-font imports, without changing package manifests/lockfile.
- Shared buttons, inputs, tables, page primitives, metric cards and navigation
  presentation; neutral secondary native buttons/chips, clearer native cards
  and more consistent text leading.
- See `docs/modules/app-visual-refresh.md` for scope and design decisions.

## Boundary

No routes, menu model, copy, DOM hierarchy, event handlers, auth, API calls,
permissions, money calculations, database or offline logic changed. The two
sidebar brand rows now match the existing 64px topbar. No new behaviour or
layout model was introduced. The onboarding guide describes the same flows,
so it needs no instruction changes.

## Validation

- Types package build; web, mobile, portal and shared UI typechecks: pass.
- Lint of changed web/mobile/portal TypeScript files: pass.
- Existing web no-accent-border and stacked-table tests: 7/7 pass.
- Existing mobile motion/preference tests: 12/12 pass.
- Expo web export: pass (1,636 modules).
- Local Next dashboard with synthetic, request-intercepted school data:
  light/dark desktop and 390px web render; no page errors, no phone overflow.
  Computed heading font resolves to DM Sans. No production data was read.
- Expo web sign-in at 390px: no page errors or horizontal overflow.
- `git diff --check`: pass.

## Limits

Browser fixtures exercise rendering, not backend integration. Android/iOS
hardware smoke and a full screen-by-screen audit of every module remain open.
The existing full Playwright integration suite needs its disposable database,
Redis and API environment; it was not run. This is a shared visual-system pass,
not a claim that every bespoke screen has been individually redesigned.

## Second pass — stronger reference direction and mobile review

Owner feedback: first pass was too close to the old appearance; requested a new
look informed by the supplied images and mobile screenshots.

Added the illustrated welcome treatment, gold text marker, dark emerald rail,
mint/gold metrics, bolder headings and a two-column phone metric presentation.
Native home headers, school overview tiles and sign-in typography now follow
the same visual direction. All existing actions, permission gates and data
bindings remain. No auth/device-lock bypass was added: native staff presentation
was inspected through a temporary component-only fixture, removed after export.
Screenshot labels distinguish that fixture from the actual responsive web app.

Verification and captures are updated in the PR review folder. Device smoke and
the full backend-integrated E2E suite remain outstanding.

Second-pass results: mobile, web and shared UI typechecks pass; changed TS/TSX
lint passes; 7 existing web border/table tests pass; Expo web export passes.
Fresh browser render: no page errors at light/dark desktop, no horizontal
overflow at 320/390/430/768px, no clipped metric values. The topbar now wraps
without removing controls at narrow widths. Mobile drawer opens and closes.
The isolated native component preview renders without page errors/overflow.
`git diff --check` passes. Android/iOS runtime remains unverified.
